# Prettier config and one-time repo-wide format pass

## Assumptions

These apply to all three plans in this series (01 Prettier, 02 ESLint, 03 CI workflow):

- This is a **single npm package** at the repo root (no workspaces, no client/worker package
  split). One Prettier config, one ESLint config, one set of scripts.
- Tooling-only change. No application logic, no behaviour changes, no dependency upgrades of
  existing deps. The only source edits allowed are whatever Prettier's own formatter produces
  (this plan) and narrowly targeted ESLint accommodations (plan 02).
- `printWidth: 100` is chosen deliberately, not by default. Measured on the current tree
  (excluding the generated `worker-configuration.d.ts`): 284 lines exceed 80 columns but only
  54 exceed 100 — the code was clearly written to a ~100-column budget. At width 100 the format
  pass rewrites 18 of 45 TS/TSX files (~457 changed lines); at width 80 it rewrites 33 files.
- Historical documents are not reformatted: `PLAN.md` (the original spec) and `.claude/`
  (archived plan files) go in `.prettierignore`.

## Objective

Add Prettier to the repo with a committed `.prettierrc` and `.prettierignore`, add `format` and
`format:check` npm scripts, and land one mechanical repo-wide `prettier --write` pass so that
`npm run format:check` is clean at HEAD. OUT of scope: ESLint (plan 02), any CI workflow
(plan 03), and any hand-written change to source files — every source edit in this plan must be
Prettier's own output.

## Context

- `package.json` (repo root) is the only manifest. Existing scripts: `dev`, `build` (`vite
  build`), `preview`, `deploy`, `typecheck` (`tsc -b --noEmit`), `test` (`vitest run`),
  `cf-typegen`, `db:migrate:local`, `db:migrate:remote`. `"type": "module"`. There is also a
  non-standard `"allowScripts"` field (npm postinstall allowlist for `workerd`/`esbuild`) —
  leave it alone.
- Source lives in `worker/`, `web/` (React 19 SPA, `.tsx`), `shared/`, `games/`, plus root
  `vite.config.ts` / `vitest.config.ts`. Verified: `npm run typecheck`, `npm run test` and
  `npm run build` all pass at HEAD, so any post-format failure is caused by this plan.
- `worker-configuration.d.ts` is a 592 KB generated Wrangler types file at the repo root. It
  must be Prettier-ignored (it is also regenerated by `npm run cf-typegen`).
- `wrangler.jsonc` is JSONC **with meaningful comments** that the team relies on. Verified
  hazard: with Prettier's default `trailingComma: "all"`, the `jsonc` parser adds trailing
  commas inside `wrangler.jsonc`. Avoid that entirely with a `.prettierrc` override (see steps)
  rather than relying on Wrangler tolerating them.
- Existing code style already matches Prettier defaults otherwise: double quotes, semicolons,
  2-space indent, `es5`-plus trailing commas in multiline literals, parenthesised arrow params.
  Do not add options that fight that (no `singleQuote`, no `semi: false`, no `tabWidth` change).
- `.gitignore` already covers `node_modules/`, `dist/`, `.wrangler/`, `.dev.vars`, `*.local`,
  `*.tsbuildinfo`.
- `migrations/*.sql` and `public/favicon.svg` have no Prettier parser; `prettier --check .`
  skips unknown extensions silently, so they need no ignore entries.

## Steps

1. Add `prettier` (`^3.9.6`, the current latest) as a devDependency: `npm install --save-dev
   prettier@^3.9.6`. Commit the resulting `package.json` + `package-lock.json` changes.
2. Create `.prettierrc` at the repo root, as JSON, with exactly:
   - `"printWidth": 100`
   - an `overrides` entry for `["**/*.jsonc", "wrangler.jsonc"]` setting
     `"trailingComma": "none"` (keeps `wrangler.jsonc` byte-identical apart from nothing — see
     step 6's check).
   Add no other options; everything else stays on Prettier 3 defaults on purpose.
3. Create `.prettierignore` at the repo root containing (one per line, with a short comment
   header explaining that generated and historical files are excluded):
   `node_modules/`, `dist/`, `.wrangler/`, `*.tsbuildinfo`, `package-lock.json`,
   `worker-configuration.d.ts`, `PLAN.md`, `.claude/`.
4. Add npm scripts to `package.json`, placed next to `typecheck`:
   - `"format": "prettier --write ."`
   - `"format:check": "prettier --check ."`
   Do not touch any existing script, including `build`, which already produces a clean build.
5. Run `npm run format` once. Expect roughly: 18 TS/TSX files reflowed under
   `worker/`, `web/`, `games/`; `tsconfig.worker.json`'s long `include` array wrapped onto
   multiple lines; and a 1-line indentation change in `README.md` (Prettier de-indents the lazy
   continuation line of ordered-list item 7, the `PUBLIC_BASE_URL:https://your-real-domain`
   line — this is a CommonMark lazy continuation and renders identically; accept it).
6. Review the diff for anything that is *not* pure reformatting:
   - `git diff --stat` should show no file outside the categories in step 5.
   - `git diff wrangler.jsonc` must be **empty** (proves the JSONC override works). If it is not
     empty, fix the override glob rather than editing `wrangler.jsonc` by hand or ignoring it.
   - No `.md` file under `.claude/` and no change to `PLAN.md` (proves `.prettierignore` works).

## Acceptance criteria

- [ ] `prettier` is a devDependency; `package-lock.json` is updated in the same commit.
- [ ] `.prettierrc` exists, sets `printWidth: 100`, and overrides `trailingComma: "none"` for
      `*.jsonc` / `wrangler.jsonc`. No other options.
- [ ] `.prettierignore` exists and lists at minimum `node_modules/`, `dist/`, `.wrangler/`,
      `*.tsbuildinfo`, `package-lock.json`, `worker-configuration.d.ts`, `PLAN.md`, `.claude/`.
- [ ] `package.json` has `format` and `format:check` scripts; no existing script was modified.
- [ ] `wrangler.jsonc` is unchanged by the format pass (no trailing commas added, all comments
      intact).
- [ ] The diff contains only Prettier-produced reformatting — no renamed identifiers, no changed
      string literals, no added/removed statements, no comment text edits.
- [ ] `npm run format:check` exits 0 on the resulting tree.

## Verification

Run all of these from the repo root; all must pass:

```
npm run format:check   # "All matched files use Prettier code style!"
npm run typecheck      # tsc -b --noEmit, no output
npm run test           # vitest run, all suites pass
npm run build          # vite build, builds both the party_dev and client environments
```

`npm run build` is the real guard that `wrangler.jsonc` still parses:
`@cloudflare/vite-plugin` reads it and emits `dist/party_dev/wrangler.json`.

## Risks / notes

- The format pass is large but mechanical. Keep it in a single commit with the config so a
  reviewer can ignore the reformatting hunks wholesale; do not mix any other change in.
- Do **not** run `prettier --write` over `dist/` — it is Prettier-ignored via step 3, but note
  that `dist/` exists in the working tree (build output, git-ignored). If `git status` shows
  `dist/` churn, that is the pre-existing build output, not part of this commit.
- If `npm install` rewrites unrelated parts of `package-lock.json` (e.g. metadata churn from a
  different npm version), keep the lockfile change in the commit anyway — CI in plan 03 uses
  `npm ci` and needs the lockfile to match `package.json`.
- Line numbers cited in plan 02 were measured **before** this format pass, so plan 02 must
  locate its edit sites by symbol, not by line number. Do not attempt to pre-empt plan 02's
  ESLint work here.
